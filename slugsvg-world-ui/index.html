SlugSvg вырос из SVG-виджета в единый pipeline для UMG-композиции и прямого рендера в world — без обязательного промежуточного render target для UI-слоя.

Задача была не в том, чтобы показать SVG в мире. Задача — сохранить обычный UI authoring, но убрать текстурную прослойку там, где весь слой уже принадлежит Slug renderer.

Этот документ — не полный API reference. Это последовательность визуальных доказательств: от draw surface до production-shaped пилота, композиционных возможностей и текущих границ решения.
Chapter 01
Draw surfaces

World становится ещё одним canvas.

Backend умеет рисовать Slug-only widget напрямую в world и использовать тот же векторный контент как decal. Для UI-слоя не нужен промежуточный render target: элементы проходят через наш renderer сразу в целевую поверхность.

Chapter 02
X-ray pilot

Пилот там, где различия нельзя спрятать.

X-ray scanner — не чистый tech sample. Это полупрозрачный игровой экран, который игрок держит в руках: композиция должна совпасть с legacy, остаться читаемой в движении и сохранить внешний runtime-контракт tool.

Legacy-реализация остаётся рядом и может быть возвращена через data asset. Поэтому visual parity сравнивается в одном проекте, а не по памяти или по отдельному макету.

Критерий

Финальный авторитет — уже собранный legacy scanner в редакторе. Figma использовалась как источник и ориентир, но не как повод передизайнить экран.

Важная граница.

Утверждение «без render target» относится к Slug UI-слою. Detector, scene feed или другой внешний визуальный источник остаются отдельной системой и могут приходить как texture/material. Пилот не требует переписывать их в вектор.

Chapter 03
From SVG to UI

Не SVG-картинка. Композиционный pipeline.

Реальный экран требует больше, чем пути и заливки. Внутри UMG Slug-контент уже сочетается с rigged animation, texture/material brushes, Slug Text и Rich Text. Эти возможности используют один renderer и остаются отдельными редактируемыми виджетами.

Animation

Rigged SVG in UMG

Authored rig motion воспроизводится внутри обычной widget-композиции, без смены surface.

Paint

Texture and material fills

SVG coverage может заполняться texture brush или анимированным UI material.

Typography

Slug Text and Rich Text

Кириллица, shaping, wrapping, разные стили и inline runs. Текст — часть Slug pipeline, а не заранее растрированная подпись.

Chapter 04
Shared transforms

Эффект принадлежит стеку, не картинке.

Lens работает как container: одна screen-space деформация применяется ко всему Slug-содержимому внутри — SVG, Slug Text, Rich Text и brush/material carriers. Это позволяет собирать экран как группу, а не повторять параметры на каждом leaf widget.

Shared screen-space LensSVG descendants
Lens with textmixed composition

Для глубины разделены две ответственности: CameraGroup задаёт общую перспективу всему стеку, а Transform3D задаёт model rotation и Z отдельному потомку. Layout остаётся двумерным, а результат виден непосредственно в UMG Designer.

Текущая область поддержки.

CameraGroup и Transform3D доказаны для UMG/Slate preview. Direct-world capture пока явно отвергает эти scopes: расширение world instance ABI оставлено отдельной задачей.

Chapter 06
Claim boundary

Что мы утверждаем. И чего пока нет.

Пилот полезен только с честной границей. Ниже — текущий proof, а не обещание универсального UI runtime.

Доказано текущими demos

  • Slug-only widget render в world без промежуточного UI RT
  • SVG render как decal
  • X-ray pilot с переключаемой legacy-реализацией
  • Texture и animated material fills
  • Rigged SVG animation в UMG
  • Slug Text и Rich Text composition
  • Shared Lens для mixed Slug content
  • CameraGroup + Transform3D в UMG Designer
  • Figma Import и debug Atlas Viewer

Формулировки ограничены показанными editor/PIE captures.

Отдельный scope / backlog

  • Interaction и hit-test parity для world UI
  • Direct-world ABI для CameraGroup / Transform3D
  • Автоматизированный pixel-golden для Designer projection
  • Перенос внешнего detector/scene content в Slug renderer
  • Финальная perf-оценка на целевых production scenes

Эти пункты не нужны, чтобы признать текущий render proof, но нужны перед расширением области применения.

Следующий шаг

Зафиксировать visual acceptance для X-ray A/B, затем использовать этот же backend в следующем world UI без копирования legacy WidgetComponent-схемы.
